# Our State RSS Feed Service Design

## Objective

Provide John with a stable public RSS 2.0 feed for new posts from Our State that Feedbin and Unread can subscribe to, while running the feed generator hourly on `johns-mac-mini-1`.

## Scope

The service publishes metadata only: post title, canonical URL, publication and modification dates, a short excerpt supplied by Our State, and an attribution link. It does not republish article bodies, images, paywalled content, or other copyrighted assets.

The source is Our State's unauthenticated WordPress REST API:

`https://www.ourstate.com/wp-json/wp/v2/posts`

The service requests no more than 20 recent posts once per hourly run. It does not authenticate, modify the source site, crawl article pages, or use Firecrawl.

## Architecture

The Studio is the source-authoring host. The Git repository is published to GitHub under John's account. A checkout on `johns-mac-mini-1` is the runtime authority.

An hourly launchd job on the Mac mini runs a Python standard-library generator. The generator fetches structured post data from the WordPress API, validates the response, creates deterministic RSS 2.0 XML, and writes `docs/feed.xml` atomically. If the generated bytes differ from the checked-in feed, a publishing script commits and pushes the change to GitHub. GitHub Pages serves the `docs` directory from the `main` branch at a stable HTTPS URL.

No inbound connection to the Mac mini is required. Feedbin reads the feed from GitHub Pages.

## Components

- `src/ourstate_rss/generator.py`: fetch, validate, normalize, and serialize post metadata.
- `scripts/update_feed.py`: command-line entry point that writes `docs/feed.xml` atomically.
- `scripts/publish.sh`: runtime wrapper that updates the feed and pushes only when content changed.
- `tests/`: fixtures and unit tests for API validation, XML escaping, stable GUIDs, ordering, and atomic no-change behavior.
- `docs/feed.xml`: published RSS document.
- `com.johnvoorhees.ourstate-rss.plist`: hourly Mac mini launchd configuration.
- `README.md`: public explanation, feed URL, source attribution, runtime, and troubleshooting.

## Feed Contract

The feed is RSS 2.0 and contains:

- Channel title: `Our State — Personal RSS Mirror`
- Channel link: `https://www.ourstate.com/`
- Channel description explaining that this is an unofficial metadata-only feed
- One item per WordPress post
- `title`: decoded text title
- `link`: canonical Our State URL
- `guid` with `isPermaLink="false"`: `ourstate-post-<WordPress ID>`
- `pubDate`: WordPress `date_gmt`, rendered as RFC 2822 UTC
- `description`: the source-provided excerpt plus an attribution link

Items are newest first. A post update changes its description or title without changing its GUID.

## Failure Handling

The updater uses a descriptive User-Agent, a 30-second request timeout, and one retry after a short bounded delay. It rejects non-200 responses, non-JSON responses, malformed post objects, unsafe non-Our-State canonical URLs, and empty result sets.

Generation occurs in memory. The updater writes a temporary file in `docs`, parses that file back as XML, and atomically replaces `docs/feed.xml` only after validation. A failed run leaves the last valid feed untouched and exits nonzero. The publishing wrapper does not commit or push after failure.

The launchd job writes stdout and stderr to `logs/` in the runtime checkout. Log files contain statuses and counts, not article content or credentials.

## Deployment

The repository is public because GitHub Pages must serve the feed without authentication. It contains no secrets. GitHub Pages publishes from `/docs` on `main`.

The Mac mini checkout uses its existing GitHub authentication. The launchd job runs hourly and at load, with an explicit PATH and working directory. The first deployment runs the publisher manually, verifies the push, loads the LaunchAgent, and then invokes it once through launchd.

## Verification

Verification requires:

1. All unit tests pass on the Studio and Mac mini.
2. The generated document parses as XML and contains the expected RSS channel and items.
3. GitHub Pages returns HTTP 200 with the generated feed.
4. The public feed passes the W3C Feed Validator without errors.
5. Requests using Feedbin's discovery and crawler User-Agent strings receive the same valid feed.
6. The loaded launchd job reports a successful exit and produces no stderr.
7. Feedbin accepts the public GitHub Pages URL.

## Operational Boundaries

The service is for John's personal feed-reading workflow. It must remain metadata-only, low-frequency, and clearly attributed. If Our State disables the API, requests removal, or changes its reuse policy in a way that makes the mirror inappropriate, the job will be disabled and the feed removed or redirected as appropriate.
